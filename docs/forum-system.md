# Forum system

For the product direction and requirements, see
[`forums/forum-idea.md`](forums/forum-idea.md). For the current implementation
status, see [`forums/forum-overview.md`](forums/forum-overview.md).

Sharply's forum is a public, indexed discussion space for gear questions,
field reports, troubleshooting, and photography knowledge. Reading is public;
creating threads and replies requires a Sharply account.

## URL structure

- `/forum` — forum home, category directory, and latest discussions
- `/forum/new` — compatibility redirect to the new-thread composer on `/forum`
- `/forum/t/:id` — thread detail and replies
- `/admin/forums` — administrator-only forum management

The forum has its own route layout so the center column owns scrolling and the
shared footer remains inside that scrollable column. The existing site header
is retained. The home page defaults to the category directory and provides a
Latest tab for the most recently active discussions. Category links expose
total discussion and reply counts and open the latest discussions filtered to
that category.

New threads and replies use the shared forum composer. It opens as a compact
floating card in the bottom-right corner without a modal backdrop. The custom
Vaul-based drawer keeps the form body scrollable, retains the default drag
interaction, and uses a minimal Lexical WYSIWYG editor with server actions for
validation and submission. The editor supports basic text formatting,
headings, lists, quotes, inline code, links, undo/redo, and Markdown shortcuts.
The `compose=thread` and
`compose=reply` query parameters preserve compose intent through sign-in and
direct links.

## Database organization

Forum tables are declared in `src/server/db/schema.ts` but live in the
PostgreSQL `forum` schema. They reference shared `app.user` and `app.gear`
records where appropriate. `config/drizzle.config.ts` includes `forum` in its
schema filter so generated migrations include these tables.

The initial table group is:

- `category` — admin-created discussion categories
- `thread` — titles, authors, status, activity, and best-answer pointer
- `post` — Lexical JSON content and minimal edit metadata
- `thread_gear` — gear links for a discussion
- `post_gear` — gear links that can later render as horizontal gear cards
- `post_edit` — compact previous-content edit history
- `report` — moderator queue for reported posts

Migration files are intentionally not generated by feature work. Apply the
schema through the project's normal migration workflow when this feature is
ready for a database environment.

## Permissions

- Anyone can read public forum pages.
- Authenticated users can create threads and replies.
- The original thread author, site moderators, and higher roles can choose the
  best answer.
- Admins create categories.
- Administrators can access the forum administration area. Moderator access is
  reserved for a later moderation workflow and is not enabled for the current
  admin page.

The initial forum taxonomy is intentionally flat: categories are listed
directly on the forum home page and are managed by admins. Grouping categories
into domains or subcategories is deferred until the community has enough
activity to justify the extra structure.

## Implementation boundary

Forum database access follows the project server layering:

- `src/server/forum/data.ts` contains Drizzle reads and writes.
- `src/server/forum/service.ts` validates input and applies auth/role rules.
- `src/server/forum/actions.ts` exposes mutation entry points to forms and
  revalidates public and admin paths.

New editor content is serialized as Lexical JSON in the existing text column.
Legacy Markdown and plain-text content remains supported through a safe
fallback renderer, so existing posts continue to display correctly. Raw HTML
is not rendered, and forum links are restricted to safe HTTP(S), internal, or
fragment URLs. Rendered posts use the same Tailwind Typography treatment as
articles and learn pages. Images, gear cards, mentions, and other custom nodes
are reserved for future Lexical extensions without changing the storage
contract.
